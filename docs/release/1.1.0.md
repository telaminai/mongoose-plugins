# mongoose-plugins 1.1.0

Requires **Mongoose 1.1.0**, Fluxtion runtime **1.1.3** and BOM **1.0.80**. Rebuild clients against the matching host version: Mongoose 1.1.0 changes public record shapes and failure behaviour. See the host release notes and client migration checklist before deployment.

Includes the complete [1.0.46.1 admin security patch](1.0.46.1.md), including loopback DNS-alias protection and exact JSON media-type checking. The new default REST bind and web CSRF requirements remain in force.

## Admin compatibility and failure visibility

- The issues panel shows quarantined processors, dead groups, incomplete shutdown, capture failures, queue loss and health failures. Local issue acknowledgement never repairs evidence or clears engine state.
- Mongoose's `stop OUTCOME (FailureKind): reason` reply is recognized. The explicit kind is displayed; engine safety-net failures are CRITICAL. Older plain-text replies remain readable.
- `StopResult.heldNames` and its failure kind are returned by `/api/server`; the shutdown banner names retained processor identities.
- `/api/agents` includes the full structured `controlStatus` and nested `overloadStates`. DEGRADED, LATCHED and retained REMOVED overload entries appear as issues even when performance counters are disabled.
- A degraded control audit displays UNVERIFIED. A healthy current snapshot is not relabelled as proof that historical evidence is complete.
- The default fatal-error policy is CONTAIN. The UI no longer says a fatal group error necessarily exits the JVM.

## Milestone 2 remains partial

This is host compatibility plus essential state visibility, not completion of every proposed admin workflow. Dedicated guided capture acknowledgement, overload-clear confirmation, kill-switch status, recent control-record lookup and replay-status panels are not implemented. The generic Commands panel exposes the registered host commands, including:

- `control.group.status <group> --json`
- `control.capture.acknowledge <group>`
- `control.audit.acknowledge <group>`
- `overload.status`
- `overload.clear <feed>`

Investigate and reconcile first: clearing a latch re-arms detection and cannot restore lost data. Capture acknowledgement clears the corresponding health alert, not the failed recording. Exporting or acknowledging a control-audit gap cannot make incomplete history verify.

The request-issue adapter reads the explicit FailureKind token from stop-command output. Generic command output does not expose a complete structured ControlReply/EvidenceStatus envelope; those issue fields stay null when unavailable. Capture-command hint text and legacy reply hints still use textual messages. Null means unavailable, never VERIFIED. A plugin-local acknowledgement is separate from engine acknowledgement and does not provide an engine failure-occurrence ledger.

Queue counters remain cumulative. Do not interpret a cleared current overload state as recovery of the lost stream. Client-specific overload choices and migration qualification remain separate from publishing these plugins.
