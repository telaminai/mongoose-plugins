# mongoose-plugins 1.0.47

Feature release for **Mongoose 1.0.33**, Fluxtion runtime **1.1.3**, BOM **1.0.80** (unchanged from 1.0.46.1).
Only `svc-admin-web` changes functionally; every other module is identical to 1.0.46.1 apart from its version.
The 1.0.46.1 security changes are included and unchanged (see [1.0.46.1](1.0.46.1.md)); upgrading from 1.0.46.1
needs no configuration change.

## svc-admin-web: failure UX, milestone 1

The console now reports failures of the running server as issues, from typed Mongoose state only
(`controlGroupStatus`, `lastStopResult`, the health service and the `queue.<path>.dropped` counters). It never
parses a `toString()`.

- **Issues panel and cards.** The Overview has a panel with group and kind filters, one section per severity and an
  "Acknowledged (still open)" section. A header pill shows the worst open issue and is never green; a strip on every
  view shows severity counts. Cards cover a quarantined processor (CRITICAL), a dead group (CRITICAL), an incomplete
  shutdown (CRITICAL, with a banner on every view), a capture close failure (DEGRADED, CRITICAL during shutdown),
  queue loss (DEGRADED), requests refused to this console (INFO, with a hint), and any other DOWN or DEGRADED health
  check. Each card shows what happened, the evidence, what is not available in this Mongoose version, the impact and
  the actions. An action that cannot be taken is disabled and says why.
- **New and extended endpoints.** `GET /api/issues`; `POST /api/issues/ack` (CSRF); `GET /api/health`.
  `/api/server` adds `lifecycle` and `lastStopResult`; `/api/agents` adds the group `controlState`, a `state` per
  processor and keeps quarantined processors; `/api/queues` adds `dropped`, `health` and `healthReason`.
  Audit start and stop refusals are `404`/`409` with the reason, not `500`.
- **Honesty rules.** No action manufactures success: acknowledging an issue never closes it and it still counts
  toward the worst severity. Facts that Mongoose 1.0.33 cannot report are listed as "not available in this Mongoose
  version" (nine of them) instead of being guessed. Blind spots of the running server (counters disabled, no health
  service, no `MongooseServer`) are reported as such, never as "no issue". A failed read becomes a `READ_FAILED`
  issue and the UI marks the data as stale ("Issues unavailable since ...") instead of showing old data as current.
- **Regression packs.** Run with `mvn -Padmin-web-it verify -pl service/svc-admin-rest,service/svc-admin-web`
  against a real Mongoose 1.0.33 server: nine REST scenarios (exact golden JSON) and eight UI scenarios (what the
  operator sees; no console or page errors, failed requests or unexpected HTTP errors). The packs are not part of
  the default build. Six tests tagged `proposed` describe behaviour that needs Mongoose changes; they are excluded by
  default and fail until it lands. See `service/svc-admin-web/docs/testing-admin-web-it.md`.

## Compatibility

Works with Mongoose 1.0.33. Against a server without a `MongooseServer`, or with counters or health disabled, the
panel degrades to the blind-spot list above rather than failing. Milestone 2 (first-loss records, capture ledger,
refusing unknown stops, replay status, dedicated cards for fenced data and `control-audit` health) follows
Mongoose 1.1.0.

## Verification

Full reactor `verify` and the `admin-web-it` profile pass; UI pack run three times with no console errors.
