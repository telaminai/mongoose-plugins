# mongoose-plugins 1.0.46.1

Security patch for 1.0.46 (Mongoose **1.0.33**, Fluxtion runtime **1.1.3**, BOM **1.0.80**). Only the admin
services change; every other module is identical to 1.0.46 apart from its version.

## Security

- **svc-admin-rest binds `127.0.0.1` by default** (was `0.0.0.0`). Off-box access now needs an explicit `host`
  (`0.0.0.0` or an interface address) together with an `authMode` (`BASIC` or `BEARER`). Both admin services log a
  warning when they are reachable off-box with `authMode: NONE`.
- **svc-admin-rest refuses browser-driven requests in `authMode: NONE`.** Previously a cross-origin `text/plain`
  POST to `/admin` or `/api/{action}` from any page in the operator's browser ran the command, as did a request with
  a rebound `Host` or `Origin: null`. Now a request whose `Origin` is not the endpoint (or is `null`) gets `403`, a
  body or `Content-Type` other than `application/json` gets `415`, and with a loopback bind a `Host` other than
  `localhost`, `127.x.x.x`, `::1` or a name in the new `allowedHosts` gets `403`. BASIC/BEARER requests are unchanged.
- **svc-admin-web enforces CSRF in `authMode: NONE`** (the default). Previously the token was skipped in that mode,
  so any page open in the operator's browser could POST admin commands (for example `server.processors.stop`)
  with a cross-origin `text/plain` request. Now every state-changing request needs the session cookie and its
  `X-CSRF-Token`, whatever the auth mode.
- **svc-admin-web refuses cross-origin and rebound requests.** A state-changing request whose `Origin` differs from
  its `Host` (or is `null`) gets `403`. With a loopback bind, a request whose `Host` is not `localhost`, `127.x.x.x`
  or `::1` gets `403` on every `/api` and `/ws` path, which stops DNS rebinding. New setting `allowedHosts` lists
  extra host names (a reverse proxy or DNS name).

## Upgrade notes

- **Relying on the old `0.0.0.0` default of svc-admin-rest** for off-box access: set `host` explicitly, and set
  `authMode` with credentials; front it with TLS.
- **Scripts calling svc-admin-rest with `authMode: NONE`** must send `Content-Type: application/json` with any body
  (`curl -X POST http://127.0.0.1:8080/admin -H 'Content-Type: application/json' -d '{"command":"help"}'`) and no
  `Origin` header. A body-less `POST /api/{action}` still works. Reaching it through another host name on a loopback
  bind needs that name in `allowedHosts`.
- **Scripts posting to svc-admin-web with `authMode: NONE`** must first `POST /api/session/login` with body `{}`,
  keep the `mongoose_admin_session` cookie, and send it with `X-CSRF-Token: <csrfToken from the login reply>`:

  ```sh
  curl -s -c jar -H 'Content-Type: application/json' -d '{}' http://127.0.0.1:8181/api/session/login
  curl -s -b jar -H 'Content-Type: application/json' -H "X-CSRF-Token: $TOKEN" \
       -d '{"arguments":["group/processor"]}' http://127.0.0.1:8181/api/commands/server.processors.stop
  ```

  BASIC/BEARER clients that authenticate with an `Authorization` header and no cookie are unchanged.
- **Reaching svc-admin-web through another host name** (proxy, DNS alias) on a loopback bind: add that name to
  `allowedHosts`.
- The published config schema (`docs/schema/schema-1.0.46.1.json`) records the new `allowedHosts` fields of both admin
  services and the `127.0.0.1` default of svc-admin-rest.
